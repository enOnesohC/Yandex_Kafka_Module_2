# Инструкция по развёртыванию приложения по фильтрации сообщений Kafka

## Шаг 1. Загрузка кода приложения
Необходимо загрузить код приложения с guthub в папку на компьютере и открыть проект в IDE

## Шаг 2. Запуск контейнеров
Для этого необходимо использовать команду:
docker-compose up 

После этого запустятся контейнеры:

- 3 контейнера kafka: обеспечивают работу брокера
- контейнер kafka-init: создаёт топики согласно заданию и прекращает работу
- контейнер kafka-ui: для доступа к kafka-ui по адресу http://localhost:8080/ui
- контейнер words-redis: хранилище списка "плохих" слов
- контейнер words-api: микросервис для "динамического" обновления списка "плохих" слов, доступен по адресу http://127.0.0.1:8000/docs
- контейнер filter-service: создаёт агентов, которые цепляются к топикам и обрабатывают сообщения согласно заданию

## Шаг 3. Тестирование

После запуска приложения нужно создать тестовый поток сообщений и создать информацию о заблокированных пользователях.

Для этого, необходимо перейти в папку Tests, открыть файл TestMain.py и запустить его.
При этом, отработают события по созданию списка заблокированных пользователей и и рассылке сообщений.

Список с заблокированными пользователями: 
BLOCKS = {
        'u1': ['u2'],        # u1 блокирует u2 -> в таблицу u2:u1
        'u2': ['u1'],        # u2 блокирует u1 -> u1:u2
        'u3': ['u4', 'u5'],  # u4:u3, u5:u3
        'u6': ['u7'],        # u7:u6
        'u10': ['u1'],       # u1:u10
    }

Рассылка сообщений:
CASES = [
        ('u2', 'u1',  'hello badword'), # u2 посылает u1 текст hello badword
        ('u1', 'u2',  'hi there'),
        ('u4', 'u3',  'badword1 badword2 badword3'),
        ('u5', 'u3',  'badword1'),
        ('u7', 'u6',  'ok'),
        ('u1', 'u10', 'text badword'),
        ('u1', 'u3',  'hello badword, badword1, badword2'),
        ('u6', 'u5',  'clean text'),
        ('u8', 'u9',  'badword1 badword and normal'),
        ('u9', 'u8',  'just a message'),
    ]

После запуска TestMain необходимо перейти в логи контейнера filter-service, должны быть следующие записи:
[2026-09-27 14:49:28,266] [1] [WARNING] В таблице blocked_users обнаружен ключ u2:u1, отправка сообщения заблокирована
[2026-09-27 14:49:28,284] [1] [WARNING] В таблице blocked_users обнаружен ключ u1:u2, отправка сообщения заблокирована
[2026-09-27 14:49:28,285] [1] [WARNING] В таблице blocked_users обнаружен ключ u3:u4, отправка сообщения заблокирована
[2026-09-27 14:49:28,287] [1] [WARNING] В таблице blocked_users обнаружен ключ u3:u5, отправка сообщения заблокирована
[2026-09-27 14:49:28,288] [1] [WARNING] В таблице blocked_users обнаружен ключ u6:u7, отправка сообщения заблокирована
[2026-09-27 14:49:28,289] [1] [WARNING] В таблице blocked_users обнаружен ключ u10:u1, отправка сообщения заблокирована 

Отправлялось 10 сообщений, заблокировалось 6, значит остальные 4 должны быть в топике filtered_messages

Необходимо открыть kafka-ui по адресу http://localhost:8080/ui и перейти в топик filtered_messagesи открыть сообщения.
Должно быть 4 сообщения, при этом, в каждом сообщении "плохие" слова должны быть заменены на "***"

Далее, при желании, можно зайти по адресу http://localhost:8000/docs , там можно просмотреть список "плохих" слов 
с помощью ручки get_words

Ручка update_words ПОЛНОСТЬЮ заменяет список "плохих" слов. 
Можно выполнить запрос update_words с телом сообщения: "string", и выполнить отправку тестовых сообщений ещё раз.
После этого, в топике filtered_messages должно появиться ещё 4 сообщения, но текст сообщения уже не будет изменён.

## Описание
Код микросервиса по "динамическому" изменения списка "плохих" слов описан в модуле BadWordsService

Код агентов по обработке потока сообщений описан в модуле StreamReader
Согласно заданию, создаётся таблица для заблокированных пользователей, заполняется тестовыми данными в тестовом модуле Tests.
К топикам messages и filtered_messages цепляем агентов и обрабатываем каждое сообщение из топика messages.

В самом начале выполняем проверку заблокированных пользователей. Если пользователь заблокирован, его сообщение не обрабатываем,
просто не отправляем.
Если пользователь не заблокирован, выполняется проверка на наличие "плохих" слов.
Сейчас список "плохих" слов тянется из redis каждый раз при обработке сообщения. 
Это неправильно, нужно будет дорабатывать данный момент, для отладки оставил как есть.

Все "плохие" слова заменяются на "***"
